# Правила проекта ProjectB для ИИ (AI Agent Rules)

@CONTEXT.md и @IMPLEMENTATION_PLAN.md часто нужны при работе над проектом.

## 1. Архитектура и Технические ограничения
* **Singleplayer Only:** Никакого сетевого кода, никаких `NetworkBehaviour`, никаких серверных проверок. Игра строго одиночная.
* **Portrait Only:** Весь UI и геймплей проектируется исключительно под вертикальную ориентацию. Базовый Aspect ratio: 9:16, с поддержкой вытянутых экранов (9:19.5).
* **Производительность — приоритет:** Целевой FPS — 60 на мобильных устройствах. Обязательно использовать **Object Pooling** для всех часто создаваемых объектов (враги, снаряды, XP-кристаллы, вылетающий урон). Минимизировать GC-аллокации (избегать `new` внутри `Update`/`FixedUpdate`).
* **Разделение логики и визуала:** Визуальная модель всегда должна быть дочерним объектом (child). Логика не должна зависеть от конкретного меша или его размеров.
* **Data-Driven подход:** Не хардкодить значения. Использовать `ScriptableObject` для всех балансируемых данных (данные героя, врагов, способностей, карточек, волн, мета-апгрейдов).

## 2. Соглашения по коммитам (Conventions)
* **Conventional Commits:** Все коммиты должны СТРОГО следовать стандарту Conventional Commits. Формат: `<type>[optional scope]: <description>` (например, `feat(enemies): add bat shooter prefab`).
* **Атомарные коммиты:** Каждый пункт плана = отдельный коммит. Не копить изменения в один гигантский коммит.
* **Коммиты только с одобрения:** Не выполнять `git commit` автоматически или самостоятельно. Делать коммит только по прямому запросу пользователя либо предлагать коммит (с сообщением) и ждать подтверждения.

## 3. Рабочий процесс и Инструменты
* **ОБЯЗАТЕЛЬНАЯ КОМПИЛЯЦИЯ (Ctrl+R):** После ЛЮБОГО изменения C# кода всегда вызывай `UnityEditor.AssetDatabase.Refresh();` (через MCP инструмент `eval`). Это необходимо, чтобы скрипты перекомпилировались и были доступны в Unity.
* **Unity CLI:** В проекте доступен инструмент `unity command` (CLI). Если стандартных MCP инструментов не хватает, используй `run_command` с вызовом `unity command <tool_name>`, чтобы выполнить тяжелые операции (например, `build`, `bake_navmesh`, и т.д.).
* **Плейсхолдеры:** Использование заглушек (кубов, сфер, капсул) — это нормальная практика для поддержания скорости разработки. Сначала функционал — затем воксельные модели.
